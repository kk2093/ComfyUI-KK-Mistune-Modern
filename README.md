# 新版文本转换（Mistune 3.0.2）

这是一个最小 ComfyUI 自定义节点，用于演示同名依赖的不同版本发生冲突，以及依赖隔离的效果。

| 项目 | 内容 |
| --- | --- |
| 节点名称 | 新版文本转换（Mistune 3.0.2） |
| 节点分类 | KK测试 → 依赖版本冲突 |
| 输入 | 文本：支持 Markdown 的多行文字 |
| 输出 | HTML文本、依赖版本，均为普通 STRING |
| 第三方依赖 | `mistune==3.0.2` |

节点执行后，下方只读的“转换结果”区域显示实际依赖版本和 HTML 源文本。HTML 不会作为网页执行。无需模型、GPU 或外部服务。

## 上传至 GitHub

1. 解压此 ZIP，打开里面的 `ComfyUI-KK-Mistune-Modern` 文件夹。
2. 将这个文件夹**里面的内容**上传至独立 GitHub 仓库的根目录。
3. 仓库首页应直接包含 `__init__.py`、`requirements.txt`、`web` 和 `examples`，不要再嵌套一层插件文件夹。
4. 两个插件分别使用两个仓库，之后通过启动器克隆安装。

## 手动对照步骤

请使用独立测试整合包进行普通安装对照；这些插件的目的就是制造同环境版本冲突。

- 本插件所用接口：`mistune.create_markdown`。
- 配套插件：旧版文本转换，要求 `mistune==0.8.4`。
- 普通模式把依赖安装到同一个 Python 环境后，后安装的版本可能覆盖先前版本；合并安装两个精确版本要求时，依赖解析器也可能直接拒绝安装。
- 完成安装后重启 ComfyUI，并刷新网页。可分别尝试 A 后 B、B 后 A 两种安装顺序，每次均重启。
- 将 `examples/双节点版本冲突对照.json` 拖入 ComfyUI，然后点击运行。两个插件各有一个输出节点，不需要额外下载显示插件，也不需要连接节点才能触发执行。
- 普通共用环境下的设计预期是：至少一个节点因缺少另一版本所需的真实接口而失败；不是通过检测启动器模式或主动校验版本号来制造失败。
- 再通过原“放心装”入口审核、确认隔离安装这两个插件，重启并运行相同工作流。设计预期是两个节点全部成功，各自显示相应的实际依赖版本。
- 每个节点都设置为输出节点并禁用执行缓存，便于每次运行观察。工作流遇到首个错误可能停止，另一节点未执行不代表它已经成功。

## 冲突原理与边界

旧节点实际调用 `mistune.Renderer`，新节点实际调用 `mistune.create_markdown`。它们使用普通的 `import mistune`；没有内置依赖、私自安装、自建隔离器、模块重载、修改搜索路径或按“放心装”开关分支。

两份 requirements 对同名发行包指定了互斥的精确版本；依赖安装失败与节点运行时接口错误属于不同阶段，应分别观察。这里的冲突范围是共用同一个 Python 环境及正常模块导入机制；其他有效隔离工具也可能解决冲突。

依赖接口放在执行函数中，因此某一个 Mistune 版本可被导入时，两个节点仍可先注册；是否能正常转换则由执行时的真实接口决定。每次改变依赖后必须重启，避免旧模块仍驻留在 Python 进程中。
